[2026-10-19] Phase 2 - Authentication & Security Guardrails (COMPLETED)
--------------------------------------------------------------------------------
What was changed:
1. Frontend Authentication & API Client:
   - frontend/package.json: Installed @clerk/clerk-react (^5.61.10) and axios (^1.20.0).
   - frontend/src/types/index.ts: Added AuthUser interface.
   - frontend/src/services/api.ts: Centralized Axios client with automatic dynamic Bearer token injection (setAuthTokenGetter) and 401 error event dispatcher.
   - frontend/src/components/auth/AuthNavbar.tsx: Top navbar integrating Clerk SignedIn, SignedOut, SignInButton, and UserButton with status indicators.
   - frontend/src/components/auth/ProtectedRoute.tsx: Authentication gate protecting queries and connections, automatically syncing Clerk token getter with Axios.
   - frontend/src/App.tsx: Configured ClerkProvider, verified backend token communication trigger (GET /api/v1/auth/me), and fallback when keys are unconfigured.
   - frontend/vite.config.ts: Configured to read frontend/.env directly for Clerk keys.
   - frontend/src/index.css: Swapped font import order to prevent CSS spec warnings.

2. Backend JWT Verification & Route Protection:
   - backend/app/models/user.py: Pydantic v2 AuthenticatedUser schema (user_id, email, first_name, last_name, org_id, session_claims).
   - backend/app/core/auth.py: Clerk JWKS verifier via PyJWKClient (RS256, expiration, issuer validation). Uses standard HTTPBearer(auto_error=False) with custom 401 Unauthorized handling (RFC 6750) and test/dev bypass support.
   - backend/app/api/v1/auth.py: Exposes GET /api/v1/auth/me protected by Depends(get_current_user).
   - backend/app/api/v1/__init__.py: Mounted auth_router under /api/v1/auth.
   - backend/app/core/config.py: Configured env_file=['.env', '../.env'] for flexible directory execution.

3. SQL AST Guardrail Engine:
   - backend/app/guardrails/validator.py: sqlglot AST parser enforcing zero-trust read-only queries:
     * Only exp.Query (SELECT, UNION, INTERSECT, EXCEPT) allowed as root statement.
     * Blocks DDL/DML mutations (INSERT, UPDATE, DELETE, DROP, ALTER, TRUNCATE, CREATE, etc.) anywhere in AST (including CTEs).
     * Rejects stacked/multi-statement queries (len(parsed) > 1).
   - backend/app/guardrails/sanitizer.py: Automatically injects DEFAULT_QUERY_ROW_LIMIT (LIMIT 100) if omitted; clamps excessive limits to maximum allowable cap.
   - backend/app/guardrails/__init__.py: Clean exports for validator and sanitizer.

4. Test Suites & Environment:
   - backend/requirements.txt: Added pytest and pytest-asyncio.
   - backend/tests/test_guardrails.py: 51 test cases covering safe SELECT queries, CTEs, mutations, stacked injections, LIMIT clamping, and dialect tests (PostgreSQL, MySQL, SQLite).
   - backend/tests/test_auth.py: 8 test cases covering 401 on missing auth, invalid schemes, expired tokens, forged signatures, missing sub claims, and dev tokens.
   - Live Clerk issuer handling: Aligned mock test payloads with active CLERK_ISSUER in .env, and prioritized dev-token bypass ahead of live JWKS parsing.
   - Root .env created from .env.example.

Why these changes were made:
- AST parsing via sqlglot prevents prompt injection and accidental mutations before queries reach the database engine.
- Stateless JWKS token verification allows the FastAPI server to validate Clerk JWTs with RS256 caching without making network requests on every call.
- Strict 401 response enforcement adheres to RFC 6750 and project security criteria.

[2026-10-20] Phase 3 - Database Connection & Schema Reflection (COMPLETED)
--------------------------------------------------------------------------------
What was changed:
1. Pydantic v2 Models:
   - backend/app/models/connection.py: DatabaseDialect enum, ConnectionParams (with credential protection and custom validator), ConnectionTestRequest, ConnectionTestResponse (latency, dialect, version), ConnectionConnectRequest, ConnectionInfoResponse (safe public metadata, zero password/secret leakage).
   - backend/app/models/schema.py: ColumnMetadata (name, type, nullability, PK, default), ForeignKeyMetadata, TableMetadata (columns, PKs, FKs, row counts, sanitized sample rows), DatabaseSchemaResponse (with pre-built summary_prompt for LLM).
   - backend/app/models/__init__.py: Centralized export of all connection and schema models.

2. Sample E-Commerce SQLite Database:
   - backend/app/db/sample_data.py: Fully seeded relational schema (customers, categories, products, orders, order_items, reviews) with foreign keys, checks, realistic prices, and ISO dates. Idempotent generator seeded at backend/demo_ecommerce.db.

3. Dynamic SQLAlchemy Async Engine Factory:
   - backend/app/db/connection.py: Normalizes postgres://, postgresql://, mysql://, and sqlite:// URLs into async drivers (asyncpg, aiomysql, aiosqlite). Detects cloud providers (Neon, Supabase) and enforces sslmode=require and pooler statement cache disabling (statement_cache_size=0, prepared_statement_cache_size=0). Implements test_connection() with error sanitization.

4. Schema Reflection Service:
   - backend/app/db/inspector.py: Asynchronous schema reflection via run_sync(inspect(sync_conn)) extracting tables, columns, PKs, FKs in < 20ms (< 2s target). Concurrently pulls top-3 sample rows with sensitive column masking ([REDACTED] on password/secret/token/key). Generates structured Markdown DDL summary for Phase 4 LLM context.

5. Multi-Tenant Session Cache & Resource Management:
   - backend/app/db/session_manager.py: Thread-safe in-memory manager mapping Clerk user_id to ActiveDatabaseSession. Handles graceful engine disposal on connection replacement, disconnect, and server shutdown (integrated into backend/main.py lifespan).

6. REST API Endpoints:
   - backend/app/api/v1/connections.py: Mounted /api/v1/connections (POST /test, POST /connect, GET /current, POST /disconnect) protected by Depends(get_current_user).
   - backend/app/api/v1/schema.py: Mounted /api/v1/schema (GET /, POST /refresh) protected by Depends(get_current_user).
   - backend/app/api/v1/__init__.py: Registered sub-routers into api_router.

7. Frontend Type Alignment:
   - frontend/src/types/index.ts: Extended DatabaseConnection, TableSchema, DatabaseSchema, and added ConnectionParams, ConnectionTestResponse, ForeignKeyDefinition. Verified clean production compilation (npm run build).

8. Test Suites:
   - backend/tests/test_connection.py: 7 tests covering URL parsing, cloud SSL/pooler settings, sample DB test, and sanitized connection error handling.
   - backend/tests/test_inspector.py: 3 tests verifying schema reflection accuracy, column types, FKs, sample rows, sensitive masking, and < 2s duration benchmark.
   - backend/tests/test_connections_api.py: 4 integration tests verifying 401 unauthenticated blocking, test connection endpoint, connect/inspect/refresh/disconnect lifecycle, and strict multi-tenant isolation across different users.
   - backend/app/core/auth.py: Enhanced dev-token handling so dev_ prefixed tokens dynamically assume unique user_ids for tenant isolation testing.

Why these changes were made:
- Guarantees strict zero-leakage security: Database passwords and raw connection strings are never returned to client endpoints or exposed in error messages.
- Neon & Supabase cloud compatibility: Disabling statement caching on pooler endpoints prevents asyncpg collision crashes when running behind PgBouncer.
- Sub-second schema reflection provides instant feedback to users while assembling semantic context for Phase 4 LangGraph agents.
- Strict multi-tenant session isolation ensures one user can never view, inspect, or query databases connected by another account.

[2026-10-19] Phase 2 - Authentication & Security Guardrails (COMPLETED)
--------------------------------------------------------------------------------
What was changed:
1. Frontend Authentication & API Client:
   - frontend/package.json: Installed @clerk/clerk-react (^5.61.10) and axios (^1.20.0).
   - frontend/src/types/index.ts: Added AuthUser interface.
   - frontend/src/services/api.ts: Centralized Axios client with automatic dynamic Bearer token injection (setAuthTokenGetter) and 401 error event dispatcher.
   - frontend/src/components/auth/AuthNavbar.tsx: Top navbar integrating Clerk SignedIn, SignedOut, SignInButton, and UserButton with status indicators.
   - frontend/src/components/auth/ProtectedRoute.tsx: Authentication gate protecting queries and connections, automatically syncing Clerk token getter with Axios.
   - frontend/src/App.tsx: Configured ClerkProvider, verified backend token communication trigger (GET /api/v1/auth/me), and fallback when keys are unconfigured.
   - frontend/vite.config.ts: Configured to read frontend/.env directly for Clerk keys.
   - frontend/src/index.css: Swapped font import order to prevent CSS spec warnings.

2. Backend JWT Verification & Route Protection:
   - backend/app/models/user.py: Pydantic v2 AuthenticatedUser schema (user_id, email, first_name, last_name, org_id, session_claims).
   - backend/app/core/auth.py: Clerk JWKS verifier via PyJWKClient (RS256, expiration, issuer validation). Uses standard HTTPBearer(auto_error=False) with custom 401 Unauthorized handling (RFC 6750) and test/dev bypass support.
   - backend/app/api/v1/auth.py: Exposes GET /api/v1/auth/me protected by Depends(get_current_user).
   - backend/app/api/v1/__init__.py: Mounted auth_router under /api/v1/auth.
   - backend/app/core/config.py: Configured env_file=['.env', '../.env'] for flexible directory execution.

3. SQL AST Guardrail Engine:
   - backend/app/guardrails/validator.py: sqlglot AST parser enforcing zero-trust read-only queries:
     * Only exp.Query (SELECT, UNION, INTERSECT, EXCEPT) allowed as root statement.
     * Blocks DDL/DML mutations (INSERT, UPDATE, DELETE, DROP, ALTER, TRUNCATE, CREATE, etc.) anywhere in AST (including CTEs).
     * Rejects stacked/multi-statement queries (len(parsed) > 1).
   - backend/app/guardrails/sanitizer.py: Automatically injects DEFAULT_QUERY_ROW_LIMIT (LIMIT 100) if omitted; clamps excessive limits to maximum allowable cap.
   - backend/app/guardrails/__init__.py: Clean exports for validator and sanitizer.

4. Test Suites & Environment:
   - backend/requirements.txt: Added pytest and pytest-asyncio.
   - backend/tests/test_guardrails.py: 51 test cases covering safe SELECT queries, CTEs, mutations, stacked injections, LIMIT clamping, and dialect tests (PostgreSQL, MySQL, SQLite).
   - backend/tests/test_auth.py: 8 test cases covering 401 on missing auth, invalid schemes, expired tokens, forged signatures, missing sub claims, and dev tokens.
   - Live Clerk issuer handling: Aligned mock test payloads with active CLERK_ISSUER in .env, and prioritized dev-token bypass ahead of live JWKS parsing.
   - Root .env created from .env.example.

Why these changes were made:
- AST parsing via sqlglot prevents prompt injection and accidental mutations before queries reach the database engine.
- Stateless JWKS token verification allows the FastAPI server to validate Clerk JWTs with RS256 caching without making network requests on every call.
- Strict 401 response enforcement adheres to RFC 6750 and project security criteria.

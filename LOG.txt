   - backend/app/models/user.py: Pydantic v2 AuthenticatedUser schema (user_id, email, first_name, last_name, org_id, session_claims).
   - backend/app/core/auth.py: Clerk JWKS verifier via PyJWKClient (RS256, expiration, issuer validation). Uses standard HTTPBearer(auto_error=False) with custom 401 Unauthorized handling (RFC 6750) and test/dev bypass support.
   - backend/app/api/v1/auth.py: Exposes GET /api/v1/auth/me protected by Depends(get_current_user).
   - backend/app/api/v1/__init__.py: Mounted auth_router under /api/v1/auth.
   - backend/app/core/config.py: Configured env_file=['.env', '../.env'] for flexible directory execution.

3. SQL AST Guardrail Engine:
   - backend/app/guardrails/validator.py: sqlglot AST parser enforcing zero-trust read-only queries:
     * Only exp.Query (SELECT, UNION, INTERSECT, EXCEPT) allowed as root statement.
     * Blocks DDL/DML mutations (INSERT, UPDATE, DELETE, DROP, ALTER, TRUNCATE, CREATE, etc.) anywhere in AST (including CTEs).
     * Rejects stacked/multi-statement queries (len(parsed) > 1).
   - backend/app/guardrails/sanitizer.py: Automatically injects DEFAULT_QUERY_ROW_LIMIT (LIMIT 100) if omitted; clamps excessive limits to maximum allowable cap.
   - backend/app/guardrails/__init__.py: Clean exports for validator and sanitizer.

4. Test Suites & Environment:
   - backend/requirements.txt: Added pytest and pytest-asyncio.
   - backend/tests/test_guardrails.py: 51 test cases covering safe SELECT queries, CTEs, mutations, stacked injections, LIMIT clamping, and dialect tests (PostgreSQL, MySQL, SQLite).
   - backend/tests/test_auth.py: 8 test cases covering 401 on missing auth, invalid schemes, expired tokens, forged signatures, missing sub claims, and dev tokens.
   - Live Clerk issuer handling: Aligned mock test payloads with active CLERK_ISSUER in .env, and prioritized dev-token bypass ahead of live JWKS parsing.
   - Root .env created from .env.example.

Why these changes were made:
- AST parsing via sqlglot prevents prompt injection and accidental mutations before queries reach the database engine.
- Stateless JWKS token verification allows the FastAPI server to validate Clerk JWTs with RS256 caching without making network requests on every call.
- Strict 401 response enforcement adheres to RFC 6750 and project security criteria.

   - backend/app/api/v1/__init__.py: Registered sub-routers into api_router.

7. Frontend Type Alignment:
   - frontend/src/types/index.ts: Extended DatabaseConnection, TableSchema, DatabaseSchema, and added ConnectionParams, ConnectionTestResponse, ForeignKeyDefinition. Verified clean production compilation (npm run build).

8. Test Suites:
   - backend/tests/test_connection.py: 7 tests covering URL parsing, cloud SSL/pooler settings, sample DB test, and sanitized connection error handling.
   - backend/tests/test_inspector.py: 3 tests verifying schema reflection accuracy, column types, FKs, sample rows, sensitive masking, and < 2s duration benchmark.
   - backend/tests/test_connections_api.py: 4 integration tests verifying 401 unauthenticated blocking, test connection endpoint, connect/inspect/refresh/disconnect lifecycle, and strict multi-tenant isolation across different users.
   - backend/app/core/auth.py: Enhanced dev-token handling so dev_ prefixed tokens dynamically assume unique user_ids for tenant isolation testing.

Why these changes were made:
- Guarantees strict zero-leakage security: Database passwords and raw connection strings are never returned to client endpoints or exposed in error messages.

- Strict multi-tenant session isolation ensures one user can never view, inspect, or query databases connected by another account.

--------------------------------------------------------------------------------
What was changed:

3. Multi-Provider LLM Inference Client:

     * Primary: Groq (ChatGroq with llama-3.3-70b-versatile, temperature 0.0 for SQL, 0.2 for summaries).

     * Test / Mock provider support for deterministic unit tests and offline testing.

4. System Prompts:
   - backend/app/agent/prompts.py: Designed SQL_GENERATION_SYSTEM_PROMPT, SQL_SELF_CORRECTION_SYSTEM_PROMPT, and NARRATIVE_SUMMARY_SYSTEM_PROMPT enforcing dialect awareness, schema bounds, read-only SELECT constraints, and concise executive takeaways.

5. Chart Recommendation & Summary Services:
   - backend/app/services/chart_service.py: Implemented ChartRecommendationService with deterministic heuristics mapping column cardinality and temporal/numeric/categorical types to Recharts formats (line, bar, pie, none).
   - backend/app/services/summary_service.py: Implemented SummaryService generating 2–3 sentence plain-English business narratives with rule-based fallback for empty and single-row results.
   - backend/app/services/__init__.py: Exported services.

6. LangGraph Agent State Machine:
   - backend/app/agent/state.py: Defined AgentState TypedDict capturing full query lifecycle context.
   - backend/app/agent/graph.py: Built and compiled stateful workflow graph:
     * generate_sql_node -> validate_guardrails_node -> self_correct_sql_node (max 2 retries) -> execute_query_node -> generate_insights_node.
     * Enforced zero-tolerance AST guardrail block (0 retries) on fatal DDL/DML mutations (INSERT, UPDATE, DELETE, DROP, etc.).
   - backend/app/guardrails/validator.py: Enriched ValidationResult with error_code derivation.

7. REST API Endpoint:
   - backend/app/api/v1/queries.py: Exposed POST /api/v1/queries/ask protected by Depends(get_current_user), verifying active database session from DatabaseSessionManager and running LangGraph pipeline.
   - backend/app/api/v1/__init__.py: Mounted queries_router under /api/v1.

8. Frontend Type Alignment:
   - frontend/src/types/index.ts: Extended ChartConfig and QueryResult with flexible camelCase and snake_case properties to ensure seamless UI integration. Verified clean compilation (tsc -b && vite build passed in 494ms).

9. Test Suites:
   - backend/tests/test_agent.py: 16 tests covering SQL fence extraction, chart heuristics, summary generator, safe QueryExecutor, guardrail security blocking, self-correction on syntax error, and max 2 retry cap.
   - backend/tests/test_queries_api.py: 5 integration tests covering 401 unauthenticated, 400 no connection, 422 blank validation, successful end-to-end question answering against demo database, and status='blocked' guardrail response.
   - Full test suite passed: 94 tests passed, 0 failures, 0 regressions across all phases.

Why these changes were made:
- Stateful LangGraph multi-step graph allows automatic recovery from minor SQL syntax or column name hallucinations without exposing raw errors to end users.
- AST guardrails via sqlglot combined with read-only transaction rollbacks and 10s timeouts provide defense-in-depth against malicious prompt injection and DoS.
- Heuristic chart selection delivers instantaneous, zero-cost visualization recommendations tailored directly for Recharts.
- Multi-provider fallback prevents vendor lock-in and eliminates downtime during LLM API outages or rate limits.
